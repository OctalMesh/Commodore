<h1></h1>

Дякуємо за ваш інтерес до **Commodore**!

Commodore є спільним CLI-рушієм і SDK, що використовується в проєктах OctalMesh.
Ми вітаємо внески, особливо виправлення, які покращують надійність,
документацію, досвід розробки та поведінку CLI для різних ролей.

## Перед початком

> [!IMPORTANT]
> Відкрийте issue перед початком роботи над великою функцією або зміною
> поведінки. Невеликі виправлення багів, оновлення документації та точкові
> рефакторинги можна надсилати відразу як pull request.

Якщо ви повідомляєте про проблему або пропонуєте зміну, додайте:

- Що ви очікували побачити
- Що сталося фактично
- Кроки для відтворення проблеми
- Відомості про ОС і shell, які мають значення
- Деталі конфігурації `.commodore`, якщо вони впливають на поведінку

## Вимоги до Pull Request

Робіть pull request-и вузькими за змістом і зручними для рев'ю:

- [ ] Одна логічна зміна на pull request
- [ ] Наявна структура проєкту та правила найменування збережені
- [ ] Документація оновлена при зміні поведінки CLI або публічного SDK
- [ ] Тести додані або оновлені, якщо зміна впливає на поведінку, яку можна
      перевірити автоматично
- [ ] Немає не пов'язаних із задачею змін форматування

## Нотатки для розробки

Цей репозиторій містить і standalone-бінарник `commodore`, і публічний Go SDK
у `pkg/sdk`.

| Область              | Нотатки                                                                                  |
|----------------------|------------------------------------------------------------------------------------------|
| **Поведінка CLI**    | Визначається файлами конфігурації `.commodore`, які знаходяться під час виконання        |
| **Ролі**             | Реалізовані окремо - зберігайте узгодженість між ними                                    |
| **Семантика команд** | Оцінюйте як для прямого використання CLI, так і для споживачів SDK                       |
| **Публічний SDK**    | `pkg/sdk` - стабільний публічний API, критичні зміни потребують навмисного версіонування |

> [!NOTE]
> Зміни семантики команд або публічних інтерфейсів SDK слід спочатку обговорити
> в issue, оскільки вони можуть вплинути на зовнішніх споживачів, що будують
> рішення на основі Commodore.
